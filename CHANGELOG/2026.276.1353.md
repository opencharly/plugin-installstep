# 2026.276.1353 — fix(deploy): record the actually-installed packages as system-package teardown targets (charly#771 part 2 of 3)

## Summary

`charly deploy del` teardown removes the packages a deploy **declared**, not the ones it **installed**. This is **part 2 of 3** of **opencharly/charly#771**; part 1 (`opencharly/spec` `v0.2026276.1337`) is merged and tagged and supplies the contract this leg consumes; part 3 is the `charly` leg that supplies the four per-format queries and runs the accepting bed.

**Measured defect** (from `check-kind-host-vm` run `2026.276.1228`, `cleanup-check-kind-host-member`): the venue's base already provides `curl`/`iptables`/`ca-certificates`, so the install (which uses `--needed`) **skips** them — but the teardown still names them, and pac refuses the whole transaction:

```
:: removing curl breaks dependency 'curl' required by pacman / gettext / libelf / tpm2-tss
:: removing iptables breaks dependency 'libxtables.so=12-64' required by iproute2
error: failed to prepare transaction (could not satisfy dependencies)
reverse: package-remove failed: exit status 1
```

`kit.RunReverseOps` logs and continues, so the packages charly *did* install are left behind. apt/dnf are worse: `apt-get purge` of a base package succeeds and cascade-removes dependents.

**What lands**

- **`present_probe.go` (new)** — the delta computer:
  - `systemPackagesTeardownDelta(declared, presentStdout) []string` — the pure subtraction, always non-nil;
  - `probePresentPackages(ctx, deps, st) (string, bool)` — renders the format's `present_template` into the same install context and runs it on the venue via `deps.Exec.RunCapture`, returning the probe's stdout.
- **`plugin.go`** — the probe runs at the **top** of `case *spec.SystemPackagesStep:`, *before* the install (the venue's already-present set is a property of the venue *before* the install), and sets `st.Installed`. **No other case arm is touched.**
- **`present_probe_test.go` (new)** — this repo's **first** tests: six subcases on the pure delta, four at the `execDeployStep` wiring level via a capture-only `spec.DeployExecutor` double.
- **`go.mod`** — `spec v0.2026273.203` → `v0.2026276.1337` (the leg-1 tag, resolved through the Go proxy).

**Two contract points that decide whether this works:**

1. **The subtraction space.** The pac install template renders **raw** declared names (`{{range .Packages}} {{.}}{{end}}` → `curl=8.0`) while the uninstall template renders **stripped** ones (`{{pkgName .}}` → `curl`). A direct string comparison would never match, so the delta would silently equal the **full declared list** — this bug, unchanged, behind a green-looking implementation. Every comparison therefore goes through `buildkit.PkgName`, the one canonical strip (R3), the same function the uninstall template uses.
2. **nil vs empty.** `Installed == nil` means *not determined* → `Reverse()` falls back to `Packages` (prior behaviour). A **non-nil empty** slice is *authoritative* → **no removal op at all**. So a probe that cannot answer must leave it **nil**, never empty: an empty answer records no removal, silently leaving every package behind, which is worse than the bug being fixed. All three cannot-answer paths (no `present_template` configured, render failure, run error or non-zero exit) return `ok=false`, leave `Installed` nil, and print a one-line `stderr` note.

**Transitional state, stated plainly:** every format's `present_template` is **empty today** — leg 3 supplies the four queries in `charly/charly.yml`. An empty `present_template` is therefore the *normal* path right now, and it preserves the prior behaviour exactly. That path is asserted, not assumed (see the mutation evidence below).
